## About the Project

Reverse engineering of the factory head unit (Honda Display Audio 7", Mitsubishi Andromeda, Tegra 3, Android 4.2.2) on a Brazilian 2017 Honda Civic EXL. Primary objective: eliminate the startup "Warning / Disclaimer" screen that appears whenever the car is turned on, by building a custom auto-OK APK and smali patches without relying on paid tools like Honda Hack.

## 🎉 Project Completed — 2026-10-16 (Phase 7) & 2026-10-29 (Phase 10)

- **Phase 7 (2026-10-16):** Warning suppressed via an autonomous auto-OK APK (`AutoOk` v0.5.4 in production).
- **Phase 10 (2026-10-29):** Warning **completely eliminated from the boot flow** via a 1-instruction smali patch in `DaLauncher.apk` (`OpeningDivideActivity.smali:671`). Intermediate Eco screen is reduced to ~1s via Phase 10.1 (second patch, `EcoFragment.smali:3094`). CarPlay projects immediately, navigation works normally, 0 crashes. Details in [`docs/en/fase10-deploy-2026-10-29/README.md`](docs/en/fase10-deploy-2026-10-29/README.md).

`AutoOk` is retained as a safety net.

## What Was Done (Technical Summary)

- APK `AutoOk.apk` in `/system/app/AutoOk.apk` — monitors logcat, detects Warning Activity, triggers `su -c "input tap 400 350"`.
- ARM setuid `su` in `/system/xbin/su` (mode 06755, from root-honda) — permanent root access.
- Deployment via **EvilValet**: OTA package `SwUpdate.mdt` signed with public AOSP testkey, accepted by the recovery on Brazilian firmware `1.F187.16`, `rom_type` `0040`.
- Phase 10 Smali patch: bypasses disclaimer display directly inside `DaLauncher.apk`.

## Practical Guidelines

1. **Before any modification to `/system` on the car:** ensure the rollback package is built and ready. Safety net is mandatory. **Note the two distinct rollback packages:**
   - `tooling/ota-build/output-rollback/` — **AutoOk rollback**: removes `AutoOk.apk` + `su`. Generated by `prepare-pendrive-rollback.sh` without arguments.
   - `tooling/ota-build/output-dalauncher-restore/` — **DaLauncher restore** (Phase 10): reverts the disclaimer smali patch. Must be explicitly specified: `prepare-pendrive-rollback.sh /dev/sdX tooling/ota-build/output-dalauncher-restore`.

2. **Never edit code inside `tooling/references/*` directly.** Those are third-party repository clones. Use monkey-patching in `tooling/ota-build/`.

3. **Prefer static analysis on PC.** Full `/system` dumps available in `tooling/apks-dumped/dump-0040/` (197MB covering `/system/app`, `/system/vendor/app`, `/system/framework` (partial), `/system/etc`, `build.props`).

4. **For APK modifications:** rebuild via `our-apk/`, re-sign with apksigner, copy to overlay, rebuild OTA via `python3 tooling/ota-build/build.py`.

## Conventions & Required Testing

- Documentation in Markdown.
- **Mandatory testing for logic code**:
  - `our-apk/` (AutoOk): pure logic (logcat needle matching, temporal deduplication, tap decisions) is decoupled from Android framework edges and tested via JVM/JUnit without emulators or devices.
  - `tooling/**/*.py` (OTA package generators): unittests assert invariants of generated artifacts: loop-break present (`mv SwUpdate2.txt` + `rm /cache/.copy_complete`), no assertions that could abort recovery (`assert(`/`abort(`), `set_perm` only in `/tmp`, busybox `chown`/`chmod` via `run_program` in `/system`.
  - Reusable test suite: `python3 -m unittest discover -s tooling/ota-build/tests`. Runs in CI (`.github/workflows/ci.yml`).
